Estándares de gobierno, seguridad e integración

Documento ejemplo con controles obligatorios para soluciones empresariales.

Uso esperado Este documento le indica al agente qué restricciones son no negociables y qué decisiones requieren comité, excepción o revisión de seguridad.

Controles mínimos de gobierno

TemaEstándarCriterio
IdentidadToda solución corporativa debe integrarse con identidad centralizada.No se permiten usuarios locales permanentes para procesos productivos.
AmbientesDeben existir al menos ambientes de desarrollo, pruebas y producción.No se promueven cambios directos a producción.
TrazabilidadToda operación crítica debe dejar rastro auditable.Se exige logging de eventos funcionales y técnicos.
SegregaciónLa aprobación de despliegues y accesos privilegiados debe estar segregada.No puede coincidir solicitante, aprobador y ejecutor.
DatosLos datos sensibles requieren clasificación y reglas de retención.Se debe identificar si hay datos personales, financieros o confidenciales.

Estándares de integración

  • Preferir integración por API administrada sobre intercambio manual de archivos.
  • Usar eventos para desacoplar procesos cuando existan múltiples consumidores.
  • Toda interfaz debe tener dueño funcional y técnico, contrato y política de versionamiento.
  • Las integraciones síncronas se reservan para casos con necesidad real de respuesta inmediata.
  • Toda interfaz crítica debe definir manejo de errores, reintentos y monitoreo.

Estándares para capacidades de IA

ControlDescripciónAplicación
GroundingLas respuestas deben apoyarse en conocimiento autorizado.Evita recomendaciones basadas solo en conocimiento genérico.
TrazabilidadSe debe conservar evidencia de decisiones y salidas críticas.Útil para auditoría y mejora continua.
Human reviewCasos de alto impacto requieren validación humana.Arquitecturas, decisiones regulatorias y respuestas externas.
Prompt disciplineLos prompts base deben ser aprobados y versionados.Disminuye deriva y respuestas inconsistentes.
Scope limitsEl agente debe declarar lo que no puede inferir.Evita afirmaciones sin respaldo documental.

Criterios de escalamiento a comité

  • Uso de tecnología no estándar o no aprobada.
  • Tratamiento de datos sensibles o regulados.
  • Cambios significativos en identidad, integración o modelo de datos maestro.
  • Dependencia de componentes críticos sin plan de contingencia.
  • Desviación sustancial del presupuesto o del roadmap aprobado.
